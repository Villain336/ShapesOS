# Marketr Phase 9 — Spec-First Research Report

Research-only. No spec, no code, no commits. Compiled 2026-09-26.

## 1. Agent orchestration patterns

### Central manager vs. handoffs (OpenAI Agents SDK)
- **Two supported patterns:** Handoffs (transfer control *and* full conversation history to a specialist — decentralized) vs. Agents-as-Tools / manager pattern (`agent.as_tool()` — the main agent stays in control and gives workers only the task input).
- **Guidance:** central manager is better when orchestrating multiple specialists or preserving a single decision owner. "Don't use multiple agents simply because they sound more advanced — start with a single agent and specialize only when you see a clear benefit."
- Sources: OpenAI Agents SDK multi-agent deep research (https://github.com/stephendenisedwards/micro-x-agent-loop-python/blob/HEAD/documentation/docs/research/openai-agents-sdk-multi-agent-deep-research.md); Agents SDK skill summary (https://github.com/0xabdullah27/cloud-native-hackathon-ii/blob/HEAD/.claude/skills/openai-agents-sdk/SKILL.md).

### Orchestrator–workers (Anthropic — "Building Effective Agents," Dec 2024)
- Anthropic documents five workflow patterns in rising order of complexity: prompt chaining → routing → parallelization → **orchestrator–workers** → evaluator–optimizer. Open-ended, unpredictable-step problems fit agents; predictable, well-scoped tasks fit fixed-path workflows.
- Core philosophy: "simple, composable patterns outperform heavyweight frameworks"; "find the simplest solution possible, and only increase complexity when needed"; agents require well-designed tools, extensive sandbox testing, **guardrails, and human checkpoints** to manage compounding error risk.
- Anthropic's multi-agent research system: lead agent plans and synthesizes; parallel subagents get clean delegation packets (objective, output format, tools/sources, task boundaries). Token spend scaled with performance (token usage alone explained ~80% of variance) — i.e., the pattern's real benefit is parallel, isolated token budget, not emergent intelligence.
- Sources: Anthropic engineering article https://www.anthropic.com/engineering/building-effective-agents; distillations at https://github.com/zasmail/cca-prep/blob/HEAD/research/notes/blog-building-effective-agents.md, https://ai-magazine.com/how-to-build-an-ai-agent/, https://github.com/aaronlps/loop-builder/blob/HEAD/skills/loop-builder/references/pattern-orchestrator-workers.md.

### Supervisor production lessons (LangGraph ecosystem)
- **Explicit routing state:** the supervisor writes `next_agent` + `routing_reason` into shared state — observable, debuggable, auditable routing.
- **Deterministic completion flags over LLM self-assessment:** state arithmetic (`max_revisions` cutoff) forces handoff to a human regardless of what the model decides — termination guaranteed by code, not by the model.
- **Partial failure is normal:** give every worker an `on_error` fallback node; don't propagate raw worker errors into the shared state or one bad worker poisons the whole run.
- **Shared history cost:** token cost grows superlinearly with shared history — workers should receive only their slice.
- **Recursion limits as circuit breakers:** cap graph recursion at ~15–25 hops to bound runaway loops.
- **Avoid prebuilt abstractions in production:** hand-roll the state schema rather than using `create_supervisor()` — more control over context.
- LangGraph three topologies: Supervisor, Swarm/peer-to-peer (no central router), Hierarchical (supervisors as nested subgraphs).
- Human-in-the-loop: `interrupt()` pauses at a named boundary, preserves state, resumes from durable state; "the proposal is created automatically but execution waits for a human or external policy system."
- Sources: https://abstractalgorithms.dev/langgraph-multi-agent-supervisor-pattern; https://github.com/zephyrex21/ai-engineering-roadmap/blob/HEAD/phases/14-agent-engineering/13-langgraph-stateful-graphs/docs/en.md; https://github.com/mrinalcom/research-crew (working supervisor+HITL reference); https://github.com/h3xkatana/kube-dojo.github.io/blob/HEAD/src/content/docs/ai-ml-engineering/frameworks-agents/module-1.3-langgraph-for-agents.md.

### Empirical failure evidence (Cemri et al., "Why Do Multi-Agent LLM Systems Fail?")
- **14 failure modes across 3 categories:** 41.8% specification/design failures, 36.9% inter-agent misalignment, 21.3% verification gaps. Failure rates across evaluated frameworks: **41–86.7%**. Failures stem from inter-agent communication, not individual agent limits; tactical fixes yield only ~14% gains — structural redesign is what works.
- Paper: https://arxiv.org/abs/2503.13657.

### Practical production rules
- **Routing-table triggers, not LLM judgment:** "explicit routing triggers outperform 'collaborate when useful'"; cross a domain boundary → review stops being optional. Consultation triggers should be a routing table.
- **Silos vs. committees (Ka Ling Wu, Sep 2026):** don't make agents do the same task the same way (silos) or all work on everything (committees).
- **Claude Agent SDK governance pattern:** subagent gets clean task-specific context; only summarized results return to the orchestrator; narrow per-subagent tool allow-lists; capped turns and cost ceilings; the write-capable action is a *request* drafted by the LLM but executed by a **separate non-LLM service only after human approval**.
- **Context rot (Chroma research):** context quality degrades over agent turns; long-horizon agents need active summarization or reset.
- **Same-model peer review theater:** peer review between same-model instances is a martingale for correctness (arXiv:2508.17536) — don't have agents "review" each other with the same model.
- Sources: https://www.nice.com/ai-virtual-agent-platform/multi-agent-orchestration; https://medium.com/@kalingwu/multi-agent-systems-fail-at-handoffs-f43ecd6d80fd; https://github.com/bhargavlukka/claude-agent-governance-review/blob/HEAD/docs/design-review.md; https://github.com/number531/legal-api/blob/HEAD/claude-agent-sdk-prompt-best-practices-jan-2026.md.

## 2. Command-bar UX

- **Instant open (0ms):** the palette is a keyboard-initiated 100+×/day action — "keyboard-initiated actions never animate." Raycast and Vercel's ⌘K ship with *zero* open/close transition on purpose; shadcn's CommandDialog default 200ms fade+zoom should be stripped. Selected-row highlight is an instant token swap (0ms), never animated. If any motion exists: opacity-only, <100ms ceiling.
- **Keyboard contract:** ⌘K/Ctrl+K toggles (same key opens *and* closes), type immediately (no click), ↑/↓ with loop wrap, Enter runs selected, Esc closes (or pops a page), Backspace on empty query pops nested pages. On close, focus returns to the trigger element.
- **Performance budgets:** open→input focused ≤80ms; local sections rendered ≤50ms; LLM-suggested section ≤800ms typical, hidden if not back; query→first result ≤120ms; selection→action begins ≤16ms (one frame); menu JS ≤22KB gzipped. Local filtering synchronous; debounce only the async fetch, never the open.
- **Ranking:** fuzzy search with typo tolerance; **frecency ranking** (Raycast, Alfred, Spotlight rank by recent/frequent use). Standard `cmdk` lacks both — need custom scoring.
- **Structure:** all menu and context actions included, hotkeys displayed, aliases for frequent commands, grouped sections; loading states for async ops; don't overwhelm with low-level utilities.
- **Mobile:** no keyboard shortcut → a visible trigger is mandatory; full-screen or bottom-sheet, single-column list, ≥44px targets, input pinned at top.
- **Accessibility:** `role="dialog"`/`aria-modal`, input auto-focused, combobox pattern (`aria-activedescendant`), section headers as `<h3>` with `aria-labelledby`, screen-reader announcements (open, result counts, page changes), `prefers-reduced-motion` → instant transitions.
- **AI-augmented command menu (oxagen spec):** distinguishes free-form "Ask" (submitted to agent, audit-logged) from template invocations; **every interaction writes to an audit log** — Open `{route}`, Suggestion shown, Template invoked `{template_id, rendered_prompt_hash}`, Free-form Ask submitted `{prompt}` — the audit log is "the source of truth for what the user did via the menu."
- **Resting state:** the command palette is "the design nucleus" — resting UI can be nearly blank; complexity reveals on demand; visual effort shifts to the invocation moment.
- Sources: https://github.com/t1mdurden/prd-pipeline/blob/HEAD/plugins/superdesign/skills/superdesign/references/cookbook/command-menu.md; https://github.com/macanderson/oxagen/blob/HEAD/docs/specs/command-menu.md; https://github.com/abcrimson/modern-cmdk/blob/HEAD/docs/specs/cmdk-complete-rewrite-specification-v2.md; https://github.com/abcrimson/modern-cmdk/blob/HEAD/apps/docs/guide/accessibility.md; https://github.com/heymynameisrob/website-25/blob/HEAD/src/content/posts/command-k-cushion.mdx; https://github.com/yashrao2607/fileviewer.dev/blob/HEAD/pi-research-uiux-design-trends-for-developer-tools-2024-2025-s7.md.

## 3. Mission / goal-oriented frameworks

### Durable execution + checkpoints (LangGraph pattern)
- **Asynchronous approval pattern:** persist agent state *before* a human-in-the-loop wait begins; when the human decision arrives, rehydrate the same thread. "Long-running runtimes let the agent pause in place with full execution state intact."
- Checkpoint granularity: **not every step, not just the end** — at meaningful, restorable boundaries: after each step, before expensive/irreversible operations, at token-budget fractions (25/50/75%), after human approval, before yielding to human, on error, plus a time-based safety net (every ~5 min). Production best practice = hybrid.
- **Chat history alone is insufficient for recovery** (Terminal-Bench: chat-only recovery 8–13% vs. 100% for semantics-aware checkpoint/restore). "The model's context window is not durable storage."
- Explicit termination conditions beyond "LLM says done": step limit, timeout, budget exceeded, loop detection, consecutive failures. Termination must be checkable code.
- **Ralph Loop** (Geoffrey Huntley, in Codex CLI as `/goal`): agent reviews own work, fixes, re-reviews, loops until satisfied — the "are you really done?" pattern.
- **Structured step logs:** each observe→reason→act cycle emits a structured log entry (iteration number, tool, args, observation). Without per-step logs, failed loops are undebuggable. Cost control at the **loop level**, not per call (a loop can consume 10–50× the tokens of a single call).
- Sources: https://github.com/b67687/development-protocol/blob/HEAD/docs/research/ai-autonomous-execution.md; https://github.com/adilshamim8/ai-engineering/blob/HEAD/102_AI-Application-Development/04-Memory/6.%20Memory%20in%20Agentic%20Systems.md; https://github.com/wahajsayyed/ai-system-engineering/blob/HEAD/LangGraph-cookbook/langgraph_chapter_07.md; https://github.com/linda-mhmd/ai-solutions-wiki/blob/HEAD/content/glossary/agentic-loops.md; https://medium.com/@ravirchaurasia/memory-checkpoints-and-resume-logic-how-to-build-long-running-ai-agents-that-dont-forget-or-0ee16134be6a.

### Market products
- **Lindy:** human-in-the-loop as a per-action toggle — "Ask for Confirmation" makes the agent pause at that step and email the user for approval; condition-based alerts ("if this is outside your scope," "if unknown") let the agent run autonomously but escalate; **draft modes** (e.g., Gmail creates drafts instead of sending) preserve manual review; per-step feedback teaches the agent (in-context learning from corrections). Lindy's thesis: ambiguity, not length, is the real axis — anything you'd hand an intern with an SOP doc is delegable, with HITL toggled on risky steps. Setup-speed strength; Gumloop wins on visual control of branched, multi-step logic.
- **Gumloop:** visual workflow builder; AI inside steps (sort, tag, draft, light decisions via "AI Router") but the path is mostly planned — not a fully independent agent owning the whole job.
- **n8n:** "bring your own agent logic" — you own wiring, failure handling, and AI behavior; maximal flexibility, maximal responsibility.
- **Dust:** company-knowledge-grounded internal assistants and workflows — relevant to Marketr's Growth Memory grounding pattern.
- **Relevance AI:** role-specific pre-built agents (BDR, research) — workforce model.
- Key UX caution (NavThemes): "automation tools [that] save five minutes, then cost seven minutes because the approval flow is clumsy" — evaluate approval flows on mobile, email, and inside existing tools, not just in-app.
- Sources: https://github.com/lindy-ai/docs/blob/HEAD/testing/human-in-the-loop.mdx; https://www.lindy.ai/blog/gumloop-vs-n8n; https://www.cognitiverevolution.ai/living-lindy-a-no-bs-conversation-on-ai-agents-with-flo-crivello/; https://www.navthemes.com/lindy-vs-gumloop-which-ai-automation-platform-is-better-for-handling-multi-step-business-workflows/; https://www.navthemes.com/ai-tools-for-operations-management-gumloop-lindy-and-other-emerging-platforms-worth-exploring/.

## 4. Versioned playbook systems

- **Core pattern (convergent across tools):** immutable versions for history, mutable labels/pointers for environments (`production`, `staging`, `latest`). Prompt content is never edited in place — a change is a new version; **rollback is a pointer flip**, not a rewrite. Every production run records the resolved version.
- **Lifecycle gates:** DRAFT → EVAL → REVIEW → CANARY → PRODUCTION → DEPRECATED; every promotion to production requires passing evals (LLM-as-judge blocks promotion below a threshold); emergency rollback bypasses gating.
- **Git + registry hybrid:** canonical template, manifest, test cases, and change note in Git (reviewable source) → immutable registry version built from the reviewed commit → promoted with an environment pointer → run records both Git commit and registry version. Decide which authority wins if they disagree *before* an incident.
- **Market tiers:** Tier 1 personal organizers (no versioning rigor) → Tier 2 prompt CMS (PromptLayer, PromptHub — versions + release labels + non-engineer editing) → Tier 3 observability platforms with prompt management bundled (Langfuse, LangSmith, Braintrust). "The products that have grown fastest all pair prompt storage with *some* deployment mechanism (labels/environments) rather than treating prompts as static text blobs."
- **Braintrust vs. LangSmith:** Braintrust — PM-accessible playground, side-by-side comparison, versions/environments tied to release decisions, native GitHub Action evals-on-PR blocking merges on regressions. LangSmith — full trace tree, datasets + experiments, online evaluators → annotation queue → dataset → offline fix loop; guidance to redact PII at the edge, separate projects per env, sample prod traces.
- **Open-source options:** PromptHub (Langfuse-backed, label promotion, eval-gated prod, one-click rollback); Promptmetrics (Git-native, label resolution); PromptMatrix (sub-10ms serve API). Humanloop (prompt-first, enterprise) reportedly shut down Sep 2025 — W&B is the vendor-suggested migration path.
- **Gap none of them close:** they version *prompts* and trace *runs*, but none offers **business-readable procedures connected to outcomes and tenant-scoped Growth Memory** — i.e., a playbook as a growth SOP whose versions are evaluated against real marketing outcomes per tenant, not just prompt text diffs. That's the white space Marketr's Agent Playbooks would occupy.
- Sources: https://github.com/marius-manola/personal-brand/blob/HEAD/content/blog/how-to-version-prompts-for-ai-agents-in-production.mdx; https://github.com/christianggj/agentic-config-hub/blob/HEAD/skills/prompt-governance/SKILL.md; https://github.com/npci/ainxt-os/blob/HEAD/docs/ai_engine/prompt_core_registry.md; https://github.com/amang251314/prompthub; https://github.com/iiizzzyyy/promptmetrics; https://github.com/PromptMatrix/Promptmatrix; https://github.com/rahulkumarpahwa/practical-prompt-engineering-masterdotdev/blob/HEAD/DelimitersAndXML/prompt-library-market-research.md; https://www.braintrust.dev/articles/langsmith-alternatives-2026; https://github.com/data-advantage/vibereference/blob/HEAD/content/ai-development/llm-evaluation-prompt-testing-platforms.md; https://github.com/makcoder-2004/ai-engineering-sheet/blob/HEAD/07.LangChain_Ecosystem/LangSmith/LangSmith.md.

## 5. Safety for money-adjacent agents

- **Stripe MCP human-confirmation gate:** sensitive `stripe_api_write` actions (refunds, outbound payments) require a **click-to-approve URL producing a 24-hour approval token**. Governance around it: per-user OAuth session list with revoke, admin bulk revoke, **separate MCP access toggles for live vs. sandbox**, tool-call logs in Workbench, restricted keys for connected accounts. This is the closest industry precedent to Marketr's Phase 5 approval objects.
- **Scoped payment tokens (Shared Payment Token, ACP):** token encodes payment method (no card exposure), spending limits (per-transaction/daily/monthly), merchant category restrictions, expiration, cryptographic signature binding to the authorizing user.
- **LetAgentPay pattern:** `request_purchase()` → three outcomes — `auto_approved`, `pending` (wait for human), `rejected` (policy violation) → execute only if approved → `confirm_purchase()` with receipt. Request → approve → execute → reconcile, as separate steps.
- **Maker-checker for finance agents:** any money movement requires a human; specific actions always pause regardless of amount (`release_payment`, `wire_transfer`, `place_trade`); **hard deny lists** on actions an analyst can never perform (defence in depth: deny at pack *and* governance level); **amount-aware tiers** ("< $5k auto, $5k–50k manager, > $50k CFO") — flagged as the single most important finance-specific build, missing in many stacks.
- **Separation of reasoning from execution:** "Genie can help the agent understand... But Genie must never become a direct, unlimited path from a question to a financial transaction." Zero-trust orchestration layer: identity, least privilege, policy check, human approval, evidence. "A polite answer does not guarantee a safe action — guardrails belong around data access, tool selection, execution and post-action monitoring," not just the final text.
- **Architectural anti-pattern:** one agent holding every key (read market + execute trade + write ledger + *edit* ledger) — "no individual gate failed... the architecture failed: one actor could both move unbounded money and rewrite the record." Boundaries must be architectural, not bolt-on middleware.
- **Escalation rules > blanket approval queues:** approval queues ask humans to confirm everything and get "confirmed by reflex"; escalation rules stop the system on defined conditions (dollar threshold, unseen GST treatment, supplier with no coding history, variance, no source record). Triggers should relax based on **measured error rates**, not vibes — "a rate never derived from a number cannot be defended."
- **Immutable audit trail:** every tool call, governance verdict, and consent decision written to a Merkle-chained, signed log — tamper-evident by cryptography, not DB permissions.
- **Real-time risk (PYMNTS, Sep 2026):** money can settle in seconds while approvals and reconciliation lag — "faster money can actually make slow controls more dangerous... turning latency from an inconvenience into financial risk." The CFO question is "Where does real time stop?"
- **Mapping to Marketr Phase 5:** the external evidence validates Marketr's existing machinery — expiring/revocable approval objects ≈ Stripe's 24h click-to-approve token; executor re-verification ≈ zero-trust policy check at execution; budget pools ≈ per-transaction/daily/monthly token limits; append-only audit events ≈ Merkle-chained log; kill switches ≈ admin bulk revoke + live/sandbox toggles. The one genuinely new pattern to adopt: **amount-aware DoA tiers** evaluated per action/currency, which Marketr's spec currently lacks.
- Sources: https://github.com/ultrametricai/productarena/blob/HEAD/drafts/outreach/stripe/AGENTIC-ROADMAP.md; https://github.com/letagentpay/letagentpay/blob/HEAD/docs/integrations/stripe.md; https://github.com/aeoess/agent-passport-system/blob/HEAD/examples/stripe-governance/README.md; https://github.com/jessburnett/ai-orchestration-governance-infrastructure/blob/HEAD/examples/agent-governance-starter-kit/DOMAINS/finance_agent_governance_guide.md; https://github.com/day-ai-labs/maverick/blob/HEAD/docs/proposals/finance-agent-suite.md (text present; direct URL check failed — treat as secondary); https://agentive.au/blog/human-in-the-loop-ai-bookkeeping-review-checkpoints/; https://www.pymnts.com/back-office/cfo/2026/everyone-is-selling-cfos-real-time-finance-most-of-it-isnt/; https://www.youtube.com/watch?v=VAiXS6xMXf0.

## 6. What this means for Marketr Phase 9 (synthesis)

1. **The adopted direction is the one the evidence favors.** One Chief Strategy Agent as the only planning/reconciliation voice + a small executor set matches Anthropic's orchestrator–workers, the OpenAI SDK manager pattern, and LangGraph supervisor practice. Open swarms have 41–86.7% failure rates in evals and remain research-demo-grade for accountable operations.
2. **Make the orchestrator deterministic at the seams.** Explicit routing state (`next_agent` + `routing_reason`), state-arithmetic termination flags (not LLM self-assessment), explicit routing tables instead of "collaborate when useful," ~15–25 hop circuit breakers. These are cheap and convert the worst failure classes into debuggable state.
3. **Workers get clean context packets; the orchestrator gets summaries.** Marketr's `substrate.context()` already bounds per-invocation context — Phase 9 should harden it into a discipline: workers see only their slice; summaries return upstream. This contains both cost (superlinear shared-history growth) and context rot.
4. **Separate drafting from executing, enforce in code.** The governance pattern (LLM drafts a write-capable *request*; a separate non-LLM service executes only after human approval) is exactly Phase 5's executor-re-verification design — Phase 9 must not let the command bar or Chief Strategy Agent bypass it for convenience.
5. **Command bar: instant open, keyboard contract, audit everything.** 0ms open, full keyboard contract, ≤80ms focus, frecency ranking — and every agent invocation from the bar writes to the audit log (template ID + prompt hash for templated actions; full prompt for free-form asks), mirroring the oxagen pattern. It doubles as a business artifact, not just navigation.
6. **Missions = durable execution + hybrid checkpoints + explicit termination.** Persist mission state before every human wait (async approval pattern), checkpoint at restorable boundaries (event + time hybrid), give every mission a structured event timeline and checkable termination conditions. The mission object is the durable-state + event-log abstraction, not just a task list.
7. **Adopt per-step HITL toggles and escalation rules, not blanket queues.** Lindy's per-action "ask for confirmation" and the accounting world's escalation-rule discipline beat a blanket approval queue (which degrades to reflex-confirming). Draft modes for outbound artifacts (outreach drafts, campaign changes staged not live).
8. **Playbooks = Git-backed source + immutable registry + label pointers + outcome evals.** Versions immutable; `production` is a pointer; rollback is a pointer flip; every run records the resolved version. The differentiator to spec: evaluate playbook versions against real tenant outcomes (from Growth Memory), not just LLM-judge prompt scores.
9. **Add amount-aware authorization tiers.** The money research surfaces one genuinely missing piece in Phase 5: delegation-of-authority thresholds per action/currency (e.g., auto-propose under $X, two-person above), evaluated at execution time. Phase 9's spec should close this.
10. **The non-custody invariant is an architectural advantage, not just compliance.** The evidence says the safest money architecture is one where the agent *cannot* reach the money: scoped tokens, executor-side enforcement, no custody. Marketr's ZERO-custody + autopilot-never-buys posture is the strongest version of the industry's converging pattern — make it structural (the executor cannot construct a money movement without a human-signed authority), not just policy text in a prompt.

## 7. Open questions the evidence does not settle

- **How small is the "small executor set"?** Evidence says narrow specialists with clean context packets, but no source gives a number — 3? 5? 8? The right granularity for marketing executors (media, content, outreach, analytics, creative) is undetermined.
- **When does the Chief Strategy Agent ask for clarification vs. act?** The conditional-interrupt pattern (ask only when confidence < threshold) exists, but calibrating the threshold per action class is open.
- **Cost ceiling per mission:** loop-level cost caps are recommended, but no source gives a per-mission budget methodology for marketing workloads.
- **Playbook eval methodology:** what counts as a "golden dataset" for a growth playbook? Outcome-attribution (did the playbook cause the revenue lift?) is the hard unsolved piece — prompt tools evaluate text quality, not business outcomes.
- **Cross-tenant learning boundary:** `playbook_learnings` is anonymized and human-reviewed, but the evidence offers no tested mechanism for keeping anonymized patterns from leaking competitive signal between tenants.
- **Escalation-rule calibration:** measured error-rate thresholds for relaxing rules are advocated, but no marketing-specific baseline exists — Marketr would be defining it.
- **Mission interruption UX:** what a paused-for-days mission looks like on resume (stale data, changed budgets, competitor moves) is undocumented in the sources; the async-approval pattern covers state, not staleness.
- **Swarm failure evidence is eval-benchmark, not production-marketing:** the 41–86.7% failure rates come from agent frameworks on benchmark tasks, not from marketing operations — marketing-specific failure modes (duplicated outreach, contradictory channel strategy, brand-voice drift) are practitioner claims, not measured.

## 8. Proven practice vs. hype

- **Proven:** supervisor/manager orchestration with explicit state (LangGraph production users, Anthropic engineering); HITL via durable checkpoint + rehydrate; 0ms command palettes with keyboard contracts (Raycast, Linear, Vercel); immutable prompt versions with label-based promotion and rollback (Langfuse/LangSmith/Braintrust/PromptHub); human-confirmation gates with expiring tokens for money actions (Stripe MCP); escalation rules over blanket queues (accounting practice); separation of propose from execute (governance patterns).
- **Practitioner production lessons (credible, not formally evaluated):** shared-history token cost growth; context rot; routing tables over LLM judgment; per-action HITL toggles; amount-aware tiers. Multiple independent sources agree, but they are not benchmarked.
- **Vendor positioning (treat skeptically):** comparison content from Lindy/Gumloop/navthemes (each ranking itself first); Braintrust's self-comparison table. Directionally useful, not neutral.
- **Experimental/research:** multi-agent failure-rate benchmarks (real but on synthetic tasks, not marketing ops); same-model peer-review martingale result (arXiv, not yet widely replicated); context-rot measurements (one research org).
- **Hype to avoid importing:** "agent swarms" as a marketing-operations solution; peer agents reviewing each other's work with the same model; blanket approval queues as safety theater; "latest" prompt pointers in production; treating a polite agent answer as evidence of a safe action.
